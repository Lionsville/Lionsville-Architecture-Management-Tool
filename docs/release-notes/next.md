# Release notes, next version — draft

*What has landed on `main` since 2.3.0 that a user would notice, in the user's
words. Pasted into the GitHub release when it is cut, and emptied then.*

**The app is called Lionsville Architect.** The window, the menus, the About box and the installers all say the new name. Nothing else changed: your folders, your files and your settings are where they were, and this version opens them exactly as the last one did.

**Why 3.0.0 and not 2.5.0.** From this version the core is one half of a pair: a build composed from it completes the other half — where work is kept, who else has the scope open, what the page may reach — and the tool can be composed into another product without a line of this one being edited. A step in your model can also come from another author. The folder format is 7, and the upgrade path is unchanged: a folder or a `.lvarch` written by any 2.x version opens as it is, and older ones still fold forward.

**Observations, and what lies behind them.** *Observations* on the bar, and a card on every scope's home, opens a register of what the team saw — numbered, dated, where, how much it matters, how often it has been seen — with the record beside it. *Seen again* counts one more and writes the day into the record's history. Two observations that turn out to be the same are merged, with the sightings and the history kept on both records. An observation is local unless you share it; shared, every scope above reads it, may link it to a cause of its own and may merge it into one of its own — changed where it lives, as every record is.

**Analysed, as a team, into causes.** *Link to a cause…* names what lies behind an observation, existing or new, with the strength of the relationship; *Link to a deeper cause…* does the same one level further. A cause starts assumed and is marked verified once checked; a cause nobody explains is a root cause, and stops being one the moment a deeper cause is linked. The *Analysis* tab draws it: observations on the left as circles sized by impact and tinted by how often they were seen, causes in lanes, root causes on the right, and the weight of each line the strength of the link. The seam between the register or the picture and the reading pane is dragged to give either more room.

**Closed, not deleted.** An observation that was fixed, addressed or has stopped mattering is *archived*, with the day and a note on why in its history; it leaves the analysis — not drawn, not queued, not offered upward — and stays in the register under *Show archived* until *Restore* brings it back. Every observation also says who saw it, as free text.

**The working file is sealed.** A `.lvarch` is your whole organisation in one file, and it leaves through a mail, a chat, a drive or a stick. *Save a copy* now asks for a password twice — the second field is the only check there is on a password nobody can recover — and writes one opaque, encrypted blob: not the names, not the number of scopes, nothing about what is inside is readable without it. Opening one asks once, and a wrong answer is asked again with the verdict under the field. There is no unsealed export; whoever wants the zip has the password. **Every working file written before this opens as it always did** — a file is recognised by its bytes, not its name.

**Export and Open work from a home.** Both used to be greyed out on the organisation's screen and on a scope's home — the one screen the file is named after could not write it — and a `.lvarch` double-clicked while the app showed a home went nowhere at all. Both now work from either, and an opened file lands its scopes under the home you opened it on. *Save* still needs a scope open, because with nothing open there is nothing to save.

**Your machine's settings stay with the install.** What this machine does about a folder — pull on open, push after a snapshot — used to be a `.lionsville-architecture/local.json` file of ours inside your folder. It is kept by the app now. Nothing to migrate: a folder this install has not written an entry for is read from the old file, so your choices survive the move, and the old file is left exactly where it is.

**Built on, and edited by more than one person.** Where work is kept is no longer a closed list: a build composed from this one registers a place of its own, gives it a way in by button and by address, brings its own words for it in your language, draws its own strip inside this app's theme, and says in its own sentence what it costs you — the bar and the home read what it says rather than guessing. A change made by another author lands on your model through the same reducer as your own, summarised in the Activity list with their name, and *by NAME via CLIENT* where they worked through something that speaks for them. ⌘Z steps over a change that is not yours and takes back the newest that is. The bar says *Also here* with the names of whoever else has the scope open, and nothing at all when there is nobody. Two people adding the same name in the same second no longer overwrite one another: the second is refused and given another id rather than silently landing on top of the first.

**An agent without a screen.** The tools that read your landscape now work in a build that has no window at all, and a host says which of them it has rather than advertising a tier it will refuse. A call that needs a canvas is refused with a key that says so — *there is no screen here* — instead of one that means *ask again in a moment*, so a client stops retrying something that cannot work.

**In a browser, with nothing installed.** [app.architecture.lionsville.nl](https://app.architecture.lionsville.nl/) runs the newest release — this one, from now on — as a page: your work stays in that browser, or in a folder it opens for you in Chrome and Edge, and nothing is sent anywhere. Every release also carries `web-<version>.zip`, the same build with a `version.json` saying which release it is, for hosting it yourself; all it needs is a static server with an SPA fallback.

**Smaller things.** The documentation dialog stays up as you step from element to element instead of fading in again on every step. The preferences, the remembered working folder, the Recent list and the agent's token stayed where they were across the rename.

**For an agent:** `observations.list`, `observation.read`, `causes.list`, `cause.read`; `observation.record`, `observation.update`, `observation.seen`, `observation.archive`, `observation.merge`, `observation.remove`, `cause.add`, `cause.update`, `cause.link`, `cause.unlink`, `cause.remove`; `app.open` takes `observations`. `activity.list` answers `via` beside the author for a step made elsewhere. A create on an id the model already holds is refused `command.taken` — mint another and send it again. A host with no window answers `agent.noScreen` where it used to answer `agent.noAnswer`.

**On disk:** `observations/NNNN-<slug>.md` and `observations/causes/NNNN-<slug>.md` beside the decisions and the plans, and the folder format is 7. A folder written by 2.3.0 opens as it is; a folder written by this version keeps its observations, which 2.3.0 would not read. A saved working file is `application/octet-stream` rather than a zip, because it is sealed.

**The two 2.4.0 betas are folded in here**; 2.4.0 was never cut.

The reasoning is ADR-0021 and ADR-0022 in `docs/decisions/`, with the sealed working file and the web build recorded beside them.
