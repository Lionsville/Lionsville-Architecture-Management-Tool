# Release notes, next version — draft

*What has landed on `main` since 3.0.1 that a user would notice, in the user's
words. Pasted into the GitHub release when it is cut, and emptied then.*

- **Where your work is kept can say more for itself.** A build composed from
  this one registers the kind of place its work lives in, and five things about
  such a place are now its own rather than this app's guess at them.
- **Its own lines in the ⋯ menu, and its own name on the chip.** Commands that
  belong to where the work is kept — signing in, a page of its own, something
  to do to the scope that is open — are drawn in the menu under a rule, after
  everything of this app's, so there is still one place to look for what can be
  done here. And the chip in the bar says what that place calls itself now,
  rather than the name it was opened under, with its own sentence on hover and
  somewhere to go when there is something to press.
- **A refused save is explained by whatever refused it.** Until now a save that
  was not taken said this browser was full or blocked, wherever the work
  actually was — naming the wrong place and recommending a copy that is not the
  one that matters. The place that said no gives the sentence now; where it has
  already said so itself, this app adds nothing instead of a sentence about
  somewhere else.
- **A way in is offered where it is worth offering.** A button that connects to
  somewhere is not drawn when that is the place you are already working from,
  and it can say something else once you are there.
- **Connect an agent says how to reach the work where it is.** The dialog makes
  room for what the place your work is kept in has to say about reaching it: in
  the browser in place of the paragraph about the desktop, and on the desktop
  under the section about this machine's server, because there both ways in are
  real.
- **The update check is only offered where the updates are this build's.**
  *Check for Updates…* and the automatic check behind it appear where this
  app's own releases are the ones to look at, so a build that keeps its own
  updates no longer carries an item pointing at a release page that is not its
  own. Nothing changes for a copy installed from this repository's releases.

Nothing changes about the three places this repository itself keeps work in — a
folder, this browser's storage, memory: the same menu, the same three chips, the
same sentence on a refusal, the same dialog.
